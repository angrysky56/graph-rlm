## Overview

Agent Skills is an open format maintained by Anthropic for giving AI agents new capabilities. Skills are self-contained folders containing instructions, scripts, and resources that agents can discover and use to perform specific tasks.

**Key Benefits:**

- **Write Once, Use Everywhere**: Create skills once, deploy across multiple agent implementations
- **Discoverable**: Skills can be indexed and found by agents automatically
- **Structured**: Clear format specification ensures compatibility
- **Extensible**: Support for scripts, references, and assets

**Use Cases:**

- Document processing (PDF extraction, form filling)
- Code analysis and refactoring
- API integration and documentation
- Database operations
- Testing and validation
- Domain-specific workflows

## Format Specification

### Directory Structure

```
skill-name/
├── SKILL.md                    # Required: Main skill file
├── scripts/                    # Optional: Executable code
├── references/                 # Optional: Additional docs
│   ├── REFERENCE.md
│   ├── FORMS.md
│   └── domain-specific.md
└── assets/                     # Optional: Static resources
    ├── templates/
    ├── images/
    └── data/
```

### SKILL.md Frontmatter

**Required Fields:**

```yaml
---
name: skill-name
description: A description of what this skill does and when to use it.
---
```

**Name Constraints:**

- Max 64 characters
- Lowercase letters (a-z) and hyphens (-) only
- Cannot start or end with -
- Cannot contain consecutive hyphens (--)
- Must match parent directory name

**Valid Examples:**

```yaml
name: pdf-processing
name: data-analysis
name: code-review
```

**Invalid Examples:**

```yaml
name: PDF-Processing  # Uppercase not allowed
name: -pdf           # Cannot start with hyphen
name: pdf--processing # Consecutive hyphens not allowed
```

**Optional Fields:**

```yaml
---
name: my-skill
description: Skill description with keywords
license: Apache-2.0
compatibility: Requires git, docker, jq, and internet access
metadata:
  author: my-org
  version: "1.0"
allowed-tools: Bash(git:*) Bash(jq:*) Read
---
```

**Field Descriptions:**

- name (required): Skill identifier, 1-64 chars, lowercase a-z and hyphens
- description (required): What the skill does and when to use it, 1-1024 chars
- license (optional): License name or bundled license file reference
- compatibility (optional): Environment requirements, 1-500 chars
- metadata (optional): Arbitrary key-value pairs for additional info
- allowed-tools (optional): Space-delimited pre-approved tools (experimental)

### Body Content

The Markdown body contains skill instructions with no format restrictions. Recommended sections:

- Step-by-step instructions
- Input/output examples
- Common edge cases
- Error handling guidance

**Keep SKILL.md under 500 lines**. Use references for detailed content.

## Progressive Disclosure

Design skills for efficient context usage:

1. **Metadata (~100 tokens)**

   - Loaded at startup for all skills
   - Only name and description

2. **Instructions (< 5000 tokens)**

   - Full SKILL.md body loads on activation
   - Keep main file concise

3. **Resources (as needed)**

   - scripts/, references/, assets/ load on demand
   - Smaller files = less context usage

**Best Practices:**

- Keep main SKILL.md under 500 lines
- Move detailed references to separate files
- Use relative paths for file references
- Avoid deeply nested reference chains

## File References

Reference other skill files using relative paths from skill root:

```markdown
See [the detailed guide](references/REFERENCE.md) for step-by-step instructions.

Run the extraction script:
scripts/extract.py

For form templates, see:
assets/templates/form1.yaml
```

**Keep references one level deep** from SKILL.md.

## Troubleshooting

### Validation Fails

**Problem:** skills-ref validate fails

**Solutions:**

1. Check YAML syntax (missing colons, improper indentation)
2. Verify required fields are present
3. Check field constraints (length, character sets)
4. Ensure directory name matches skill name

**Debugging:**

```bash
# Enable verbose output
skills-ref validate -v ./my-skill

# Check Python installation
python -c "import skills_ref; print(skills_ref.__version__)"
```

### Agent Doesn't Use Skill

**Problem:** Agent doesn't activate the skill

**Solutions:**

1. Verify description contains relevant keywords
2. Ensure skill name matches directory name
3. Check for naming convention violations
4. Verify SKILL.md has proper frontmatter

**Good description:**

```yaml
description: Extracts text and tables from PDF files, fills forms, merges documents. Use when working with PDF documents or when the user mentions PDFs, forms, or document extraction.
```

**Poor description:**

```yaml
description: Helps with PDFs.
```

### Context Issues

**Problem:** Agent exceeds token limit

**Solutions:**

1. Reduce SKILL.md to under 500 lines
2. Move detailed content to references/
3. Split skills into smaller, focused ones
4. Use progressive disclosure effectively

### Import/Path Issues

**Problem:** Scripts fail to execute

**Solutions:**

1. Verify shebang lines are correct (#!/usr/bin/env python3)
2. Use absolute paths or relative paths from skill root
3. Document dependencies clearly
4. Test scripts in isolation

## FAQ

**Q: What is an Agent Skill?**  
A: An Agent Skill is a self-contained directory with instructions, scripts, and resources that define how an AI agent should perform a specific task.

**Q: How do agents discover skills?**  
A: Skills are discovered through standardized indexing formats and manifest files that include name, description, and location information.

**Q: Can I use skills with any AI agent?**  
A: The format is designed to be agent-agnostic, but compatibility depends on the agent implementation and its support for the Agent Skills specification.

**Q: How large should a skill be?**  
A: Keep the main SKILL.md under 500 lines and use progressive disclosure by moving detailed content to references/ and scripts/.

**Q: What languages are supported for scripts?**  
A: Python, Bash, JavaScript, and other common scripting languages depending on the agent implementation.

**Q: How do I handle dependencies?**  
A: Use requirements.txt for Python, package.json for Node.js, or document system dependencies in the compatibility field.

**Q: Can I use special characters in skill names?**  
A: No, skill names must only contain lowercase letters (a-z) and hyphens (-), and must not start or end with a hyphen.

**Q: How do I get my skill added to the ecosystem?**  
A: Create a skill following the specification, validate it, and either add it to your own agent implementation or submit it to the example skills repository.

**Q: What's the difference between metadata and compatibility?**  
A: Metadata is arbitrary additional information (author, version), while compatibility describes environment requirements (system packages, network access, etc.).

**Q: How do I test my skill?**  
A: Use skills-ref validate to check the format, then test manually by having an agent attempt to use it.
